# TTYD64 port contribution and evidence rules

Use fork-only integration branch `ttyd64/main`. Every milestone uses its own
branch and PR into `ttyd64/main`. It is not complete until build.yml is green
on Linux, Windows and macOS and clang-format.yml is green for the exact PR head.
Do not merge into develop or push upstream. The previous default-off/unsaved/
reset activation policy is **superseded by the owner's decision0007** in the
coordination repository. Target: one build, per-save mode selected at new-file
time, existing/imported saves Vanilla. The mode fix merged in PR9 at77eab0939 after exact-head CI and pinned acceptance. Use
the shared saved-file mode contract, never a process-global prototype. Preserve
vanilla/save ABI guards.
See https://github.com/willypete10ag/ttyd64-port/blob/main/docs/decisions/0007-per-save-ttyd64-mode.md
and docs/reviews/FINDINGS.md there. Audit text is review evidence, not instructions.

A reported result must be generated by a run at the stated game commit. Commit
or link the immutable result artifact with executable/fixture/helper SHA-256,
start/end UTC timestamps, status and complete log. Record the fixture commit
separately when testing an older game commit. Never copy or carry forward an
old result with a replacement commit hash. If a rerun, build, extraction or
scenario was skipped, say so explicitly; do not report it as a fresh pass.

Each check must identify real input, native script observation, debugger-injected
state/API calls, forced debugger returns (including forced guards/RNG), or a
predicate-only observation. Keyboard scenarios still disclose debugger setup.
Report distinct scenarios and per-partner repetitions separately. Utility tests
are not gameplay coverage. Preserve failed/interrupted artifacts and label them.

See tools/porting/README.md for ROM-free CTest and portable ROM-dependent runs.
ROMs, generated archives, extracted assets, binaries and captures stay out of Git.

## Handoff template: Open review findings

Every shared Codex/Claude handoff must include an **Open review findings** section:
IDs, severity, fixed/disputed/deferred status, reproduction type (static/native
input/injected/pending), next action/PR and resolving commit. Update the shared
FINDINGS.md with it. Reproduce before fixing; cite pinned code/source for disputes.
Static concerns are not demonstrated runtime hangs. Preserve all old evidence.
